# ADR-0001：采用模块化单体

- 状态：Accepted
- 日期：2026-07-03

## 决策

Photo Retouch Agent 保持单一代码仓库和统一版本，后端拆成 API 与 Worker 两个启动器，共享 Domain 和 Application 模块。

当前阶段不把资产、分析、修图任务、Agent、Provider 拆成独立微服务。

## 原因

- 核心业务仍共享任务、资产和结果的一致性边界。
- 团队需要模块隔离，但没有必要承担跨服务事务、服务发现和多版本契约。
- API 与 Worker 分进程即可隔离短请求和长模型任务。
- 物理包和架构测试可以先解决大多数代码耦合问题。

## 约束

- 每个模块必须有明确公开接口。
- 模块依赖必须单向、无环。
- 只有启动器负责创建具体 Adapter 并完成依赖注入。
- 不建立承载业务逻辑的 `common` 大杂烩模块。
